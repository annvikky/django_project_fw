## Django-project с использованием Django REST Framework (DRF)

# ТРЕКЕР ЗАДАЧ СОТРУДНИКОВ

## Проект представляет собой серверное приложение для работы с базой данных PostgreSQL. 
## Приложение обеспечивает CRUD операции для сотрудников и задач, а также предоставляет два специальных эндпоинта для получения информации о загруженности сотрудников и важных задачах.

## Трекер задач позволит компании эффективно управлять заданиями, назначенными сотрудникам, и обеспечивать прозрачность процессов выполнения задач. Это поможет в равномерном распределении нагрузки между сотрудниками и своевременном выполнении ключевых задач.

## Использование: 

Для начала работы пользователю необходимо заполнить таблицу сотрудников (Employee), между которыми будут распределяться задачи.
Заполнение таблицы возможно через админ-панель или postman (для backend). Все поля обязательны для заполнения. 
По указанному email реализована рассылка уведомления о присвоении задания. Email должен быть корпоративным (Поменять в сериализаторе).
Телефон должен содержать 11 цифр.
Задачи могут назначаться через админ-панель или postman.
Распределение задач производится между сотрудниками с учетом их занятости и важности задачи.
Одновременно у сотрудника в работе может находиться не более 5 задач. 
Если в работу поступает важная задача (это задача, от которой зависит другая задача=родительская), она распределяется в приоритете.
Ее выполнение назначается наименее загруженному сотруднику или (что приоритетнее) сотруднику, 
выполняющему родительскую задачу, если ему назначено максимум на 2 задачи больше, чем у наименее загруженного сотрудника.

Реализована возможность получения списка сотрудников с количеством активных задач
- (postman)  -/employees/busy/
Реализована возможность получения списка задач в работе
- (postman)  -/tasks/in_progress_tasks/
Реализована возможность получения списка важных задач в работе
- (postman) -/tasks/important/
Реализована возможность получения списка задач в очереди (с фильтрацией по дате готовности и родительской задаче)
- (postman)  -/tasks/queued/

Через админ панель задачу можно пометить как выполненную, она перестает быть активной и освобождает работника для назначения следующих задач.

#  Запуск проекта с помощью Docker Compose

## Предварительные требования:
- установлены Docker, Docker Compose
- создан .env файл с переменными окружения

## Шаги для запуска:
1. Клонируйте репозиторий
    ```bash
    git clone https://github.com/your-username/your-repo.git 
    cd your-repo
2. Создайте .env файл в корне проекта и добавьте в него:

    POSTGRES_DB=your_db
    POSTGRES_USER=your_user
    POSTGRES_PASSWORD=your_password
    SECRET_KEY=your_django_secret
    DEBUG=1

3. Соберите и запустите проект
    docker-compose up --build

## Проверка работы
- Проект доступен по адресу: http://localhost:8000
- 
## Компоненты проекта:

- web (Django приложение)
- db (PostgreSQL база данных)
- redis (Брокер сообщений для Celery)
- celery (Воркер Celery)
- celery-beat (Планировщик периодических задач Celery)

## Проверка работы сервисов
- Django (web)
  docker-compose exec web python manage.py migrate
  docker-compose exec web python manage.py createsuperuser
  Перейдите в админку: http://localhost:8000/admin
  Убедитесь, что фронтэнд работает и база данных подключена

- PostgreSQL
  проверьте доступность базы (подставить значения)
  docker-compose exec db psql -U $POSTGRES_USER -d $POSTGRES_DB

- Redis
  проверьте, что Redis работает
  docker-compose exec redis redis-cli ping

- Celery
  проверьте, что Celery воркер запущен и подключен к Redis
  docker-compose logs celery

  
## Остановка и удаление контейнеров
